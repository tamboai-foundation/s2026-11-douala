CONCEPTION DU SYSTÈME D'INFORMATION
Objectif 1 · Application de messagerie et de partage de contenus (CRUD) · Tâche SI-M01
==========================================================================================



1. CONTEXTE ET PÉRIMÈTRE
========================

L'application comporte trois modules développés en parallèle et reliés entre eux : Gestion
des utilisateurs, Conversations et messages, Publications et interactions. Ce document
décrit les entités, leurs attributs, leurs relations et les règles de gestion, puis leur
traduction en modèles TModeler.


Hypothèses techniques
---------------------
  - Pas de serveur back-end : toutes les données sont stockées dans une base de données
    locale, exécutée dans le navigateur (TModeler compilé en Kotlin/Wasm).
  - Les interfaces (UI) sont fournies par Foundation ; nous concevons le SI et le
    connectons à ces interfaces.
  - Chaque modèle possède automatiquement un identifiant local _id (clé primaire
    auto-incrémentée). L'identifiant serveur id existe aussi mais n'est pas utilisé tant
    qu'il n'y a pas de serveur.
  - Les 4 emojis disponibles dans l'interface fournie sont : 👍 ❤️ 😂 😮.


Hors périmètre pour l'instant
-----------------------------
  - Conversations de groupe : une conversation réunit exactement deux personnes.
  - Bio et photo de profil.
  - Chatbot.
  - Épinglage des messages (on épingle uniquement des conversations).
  - Modification et suppression des commentaires et des réponses.
  - Fil de publications (tri et pagination d'un fil).
  - Temps réel et synchronisation avec un serveur.



2. LES RELATIONS EN BREF
========================

Une relation est un lien entre deux entités. On la décrit en posant la question dans les
deux sens : « un message appartient à combien de conversations ? » (une seule) et « une
conversation contient combien de messages ? » (plusieurs).

  Cas                   | Exemple dans l'application                                                                | En TModeler
  ----------------------+-------------------------------------------------------------------------------------------+------------
  1 → 1 / 0..1          | Un message a au plus une pièce jointe                                                     | ModelField dans l'entité qui référence
  1 → plusieurs         | Une conversation contient plusieurs messages                                              | ModelField du côté « plusieurs » (Message.conversation)
  plusieurs ↔ plusieurs | Un utilisateur participe à plusieurs conversations ; une conversation a deux utilisateurs | Entité intermédiaire (ConversationMember) avec deux ModelField

Règle pratique : le champ de relation se place toujours dans l'entité qui peut dire «
j'appartiens à… ». Notation des cardinalités : 1 = exactement un ; 0..1 = zéro ou un ;
0..* = zéro ou plusieurs ; 2 = exactement deux.



3. ENTITÉS ET ATTRIBUTS
=======================

Les champs de relation sont détaillés dans la partie 4. Types TModeler : Text = TextField,
Int = IntField (Long), Bool = BoolField, Time = TimeField, File = FileField.


Module Gestion des utilisateurs
-------------------------------

> User (utilisateur)
  Attribut     | Type               | Description
  -------------+--------------------+------------
  name         | Text               | Nom affiché, obligatoire
  phone        | Text, unique       | Identifiant de connexion
  passwordHash | Text               | Empreinte (hash) du mot de passe, jamais le mot de passe en clair
  active       | Bool (défaut true) | false = compte désactivé
  createdAt    | Time               | Date d'inscription


> Session
  Attribut    | Type          | Description
  ------------+---------------+------------
  currentUser | → User (0..1) | Utilisateur connecté sur ce navigateur ; vide = personne n'est connecté


Module Conversations et messages
--------------------------------

> Conversation
  Attribut      | Type   | Description
  --------------+--------+------------
  creator       | → User | Utilisateur qui a ouvert la conversation
  createdAt     | Time   | Date de création
  lastMessageAt | Time   | Date du dernier message, sert à trier la liste des conversations


> ConversationMember (participant)
Une ligne par participant : chaque conversation en a exactement deux. Elle porte les
réglages propres à chaque personne.

  Attribut     | Type                | Description
  -------------+---------------------+------------
  conversation | → Conversation      | Conversation concernée
  user         | → User              | Participant
  pinned       | Bool (défaut false) | Conversation épinglée par ce participant
  muted        | Bool (défaut false) | Conversation en sourdine pour ce participant
  archived     | Bool (défaut false) | Conversation archivée par ce participant
  unread       | Int (défaut 0)      | Nombre de messages non lus par ce participant
  lastReadAt   | Time                | Dernière ouverture de la conversation par ce participant


> Message
  Attribut     | Type                | Description
  -------------+---------------------+------------
  conversation | → Conversation      | Conversation à laquelle appartient le message
  author       | → User              | Auteur
  text         | Text (défaut "")    | Contenu, sans limite de longueur
  replyTo      | → Message (0..1)    | Message auquel celui-ci répond
  attachment   | → Media (0..1)      | Pièce jointe unique, facultative
  edited       | Bool (défaut false) | Le message a été modifié
  deleted      | Bool (défaut false) | Le message a été supprimé (suppression douce)
  sentAt       | Time                | Date d'envoi


> Reaction (réaction à un message)
  Attribut | Type      | Description
  ---------+-----------+------------
  message  | → Message | Message concerné
  user     | → User    | Auteur de la réaction
  emoji    | Text      | Une valeur parmi 👍 ❤️ 😂 😮


Module Publications et interactions
-----------------------------------

> Post (publication)
  Attribut      | Type                | Description
  --------------+---------------------+------------
  author        | → User              | Auteur
  type          | Text                | image, audio, video ou legende
  caption       | Text (défaut "")    | Légende ; obligatoire si type = legende
  media         | → Media (0..1)      | Fichier publié ; absent si type = legende
  likesCount    | Int (défaut 0)      | Nombre total de likes
  commentsCount | Int (défaut 0)      | Nombre de commentaires
  edited        | Bool (défaut false) | La publication a été modifiée
  publishedAt   | Time                | Date de publication


> Like
  Attribut  | Type   | Description
  ----------+--------+------------
  post      | → Post | Publication likée
  user      | → User | Auteur du like
  emoji     | Text   | Type de like, une valeur parmi 👍 ❤️ 😂 😮
  createdAt | Time   | Date du like


> Comment (commentaire)
  Attribut  | Type             | Description
  ----------+------------------+------------
  post      | → Post           | Publication commentée
  author    | → User           | Auteur
  text      | Text (défaut "") | Contenu
  createdAt | Time             | Date du commentaire


> Reply (réponse à un commentaire)
  Attribut  | Type             | Description
  ----------+------------------+------------
  comment   | → Comment        | Commentaire auquel on répond
  author    | → User           | Auteur
  text      | Text (défaut "") | Contenu
  createdAt | Time             | Date de la réponse


Entité partagée
---------------

> Media (fichier)
Un seul modèle pour tous les fichiers, utilisé par Message et par Post. Il contient la
référence du fichier, jamais son contenu.

  Attribut  | Type           | Description
  ----------+----------------+------------
  file      | File           | Référence du fichier stocké dans le navigateur
  type      | Text           | image, audio ou video
  sizeBytes | Int (défaut 0) | Taille du fichier en octets, pour contrôler les limites



4. ASSOCIATIONS ET CARDINALITÉS
===============================

Chaque ligne se lit dans les deux sens. Exemple : « une conversation contient 0 ou
plusieurs messages » et « un message appartient à exactement 1 conversation ». Le champ
TModeler se place dans l'entité indiquée en dernière colonne.


Module Gestion des utilisateurs
-------------------------------
  Entité A | Card. A | Association               | Card. B | Entité B | Champ (dans)
  ---------+---------+---------------------------+---------+----------+-------------
  Session  | 0..1    | est connectée en tant que | 0..1    | User     | currentUser (Session)


Module Conversations et messages
--------------------------------
  Entité A     | Card. A | Association             | Card. B | Entité B           | Champ (dans)
  -------------+---------+-------------------------+---------+--------------------+-------------
  User         | 1       | participe via           | 0..*    | ConversationMember | user (ConversationMember)
  Conversation | 1       | a pour participants     | 2       | ConversationMember | conversation (ConversationMember)
  User         | 1       | crée                    | 0..*    | Conversation       | creator (Conversation)
  Conversation | 1       | contient                | 0..*    | Message            | conversation (Message)
  User         | 1       | écrit                   | 0..*    | Message            | author (Message)
  Message      | 0..1    | est cité en réponse par | 0..*    | Message            | replyTo (Message)
  Message      | 0..1    | a pour pièce jointe     | 0..1    | Media              | attachment (Message)
  Message      | 1       | reçoit                  | 0..*    | Reaction           | message (Reaction)
  User         | 1       | pose                    | 0..*    | Reaction           | user (Reaction)


Module Publications et interactions
-----------------------------------
  Entité A | Card. A | Association  | Card. B | Entité B | Champ (dans)
  ---------+---------+--------------+---------+----------+-------------
  User     | 1       | publie       | 0..*    | Post     | author (Post)
  Post     | 0..1    | a pour média | 0..1    | Media    | media (Post)
  Post     | 1       | reçoit       | 0..*    | Like     | post (Like)
  User     | 1       | met          | 0..*    | Like     | user (Like)
  Post     | 1       | reçoit       | 0..*    | Comment  | post (Comment)
  User     | 1       | écrit        | 0..*    | Comment  | author (Comment)
  Comment  | 1       | reçoit       | 0..*    | Reply    | comment (Reply)
  User     | 1       | écrit        | 0..*    | Reply    | author (Reply)


Schéma d'ensemble
-----------------
    Session ──(0..1)──> User
    
    User (1) ──(0..*) ConversationMember (2) ──(1) Conversation
    Conversation (1) ──(0..*) Message (0..*) ──(1) User [auteur]
    Message
     ├── replyTo    ──(0..1)──> Message
     ├── attachment ──(0..1)──> Media
     └── (1) ──(0..*) Reaction (0..*) ──(1) User
    
    User (1) ──(0..*) Post
    Post
     ├── media ──(0..1)──> Media
     ├── (1) ──(0..*) Like    (0..*) ──(1) User
     └── (1) ──(0..*) Comment (1) ──(0..*) Reply
         Comment et Reply ──(1)──> User [auteur]



5. RÈGLES DE GESTION
====================

Pour chaque règle, la colonne « Qui » indique ce qui la fait respecter : TModeler
(déclarée dans le modèle : .unique(), .default(), type de relation) ou Code (vérification
dans le code Kotlin avant d'enregistrer). Comme il n'y a pas de serveur, aucune règle
n'est garantie par un back-end.


Gestion des utilisateurs
------------------------
RG-U1   Inscription : le nom, le téléphone et le mot de passe sont obligatoires. [Code]
RG-U2   Le numéro de téléphone est unique : deux comptes ne peuvent pas avoir le même.
        [TModeler (.unique()) + Code]
RG-U3   Le nom comporte entre 2 et 50 caractères. [Code]
RG-U4   Le mot de passe comporte au moins 8 caractères. Il n'est jamais stocké en clair :
        seule son empreinte (hash) est enregistrée dans passwordHash. [Code]
RG-U5   Connexion : elle réussit seulement si le téléphone correspond à un compte actif et
        que l'empreinte du mot de passe saisi est identique à passwordHash. [Code]
RG-U6   L'utilisateur connecté est enregistré dans le modèle Session, jamais dans le
        localStorage. La déconnexion vide Session.currentUser. [Code]
RG-U7   La date d'inscription est fixée à la création et ne change plus. [Code]
RG-U8   Un utilisateur ne peut modifier que son propre profil (nom, téléphone, mot de
        passe). Un nouveau téléphone est revérifié selon RG-U2. [Code]
RG-U9   La recherche d'utilisateurs se fait par nom ou par téléphone. Elle exclut
        l'utilisateur connecté et les comptes désactivés. [Code]
RG-U10  Gestion des comptes : un utilisateur peut désactiver son compte (active = false)
        puis le réactiver. Un compte désactivé ne peut plus se connecter et n'apparaît plus dans
        la recherche ; ses messages et publications restent en place pour ne pas casser
        l'historique des autres. [Code]


Conversations
-------------
RG-C1   Une conversation réunit exactement 2 participants distincts : on ne peut pas
        ouvrir une conversation avec soi-même. [Code]
RG-C2   Il ne peut exister qu'une seule conversation entre deux mêmes personnes. Si elle
        existe déjà, on l'ouvre au lieu d'en créer une nouvelle. [Code]
RG-C3   Créer une conversation crée la Conversation et ses deux ConversationMember (le
        créateur et l'autre personne), qui doit avoir un compte actif. [Code]
RG-C4   Une conversation n'a pas de titre : l'écran affiche le nom de l'autre participant.
        [Code]
RG-C5   Épingler, mettre en sourdine et archiver sont des réglages personnels : ils ne
        changent rien pour l'autre participant. [TModeler (champs dans ConversationMember)]
RG-C6   Seuls les deux participants peuvent voir les messages d'une conversation et y
        écrire. [Code]
RG-C7   La liste des conversations affiche d'abord les conversations épinglées, puis les
        autres par date du dernier message (lastMessageAt), la plus récente en haut. Les
        conversations archivées sont masquées par défaut. Le tri est fait par la requête TModeler.
        [Code]
RG-C8   L'historique d'une conversation affiche ses messages dans l'ordre chronologique
        d'envoi. [Code]


Messages
--------
RG-M1   Un message appartient à une seule conversation et a un seul auteur. [TModeler
        (ModelField)]
RG-M2   Un message n'est pas vide : il contient du texte, une pièce jointe, ou les deux.
        Le texte n'a pas de limite de longueur. [Code]
RG-M3   L'auteur d'un message doit être l'un des deux participants de la conversation.
        [Code]
RG-M4   Un message a au plus 1 pièce jointe (image, audio ou vidéo). [TModeler (ModelField
        0..1) + Code]
RG-M5   Seul l'auteur peut modifier son message ; la modification passe edited à true.
        [Code]
RG-M6   Seul l'auteur peut supprimer son message. La suppression est douce : deleted passe
        à true, le texte et la pièce jointe sont retirés et l'écran affiche « Message supprimé ».
        La ligne est conservée pour ne pas casser les réponses qui la citent. [Code]
RG-M7   Un message supprimé ne peut plus être modifié. [Code]
RG-M8   Un message ne peut répondre qu'à un message de la même conversation. [Code]
RG-M9   L'envoi d'un message met à jour lastMessageAt de la conversation et ajoute 1 au
        compteur unread de l'autre participant. Ouvrir la conversation remet son propre compteur à
        0 et met à jour lastReadAt. [Code]
RG-M10  Une conversation en sourdine continue de compter les messages non lus, mais ne
        déclenche pas de notification. [Code]


Réactions aux messages
----------------------
RG-R1   Une réaction est l'un des 4 emojis : 👍 ❤️ 😂 😮. [Code]
RG-R2   Un utilisateur pose au plus une réaction par message. S'il choisit un autre emoji,
        il remplace le précédent ; s'il choisit le même, la réaction est retirée. [Code]
RG-R3   Seuls les participants de la conversation peuvent réagir. [Code]
RG-R4   On ne peut pas réagir à un message supprimé. [Code]


Publications
------------
RG-P1   Une publication a obligatoirement un auteur et un type parmi : image, audio,
        video, legende. [Code]
RG-P2   Le média est facultatif. Une publication de type legende n'a pas de média et sa
        légende est obligatoire (non vide). [Code]
RG-P3   Une publication de type image, audio ou video a obligatoirement un média du même
        type ; sa légende est facultative. [Code]
RG-P4   Tout utilisateur connecté peut consulter les publications des autres utilisateurs.
        [Code]
RG-P5   Seul l'auteur peut modifier sa publication (légende et média) ; la modification
        passe edited à true. Le type et le média doivent toujours respecter RG-P2 et RG-P3. [Code]
RG-P6   Seul l'auteur peut supprimer sa publication. La suppression supprime aussi ses
        likes, ses commentaires, leurs réponses et son média. [Code]


Likes
-----
RG-L1   Un like est l'un des 4 emojis : 👍 ❤️ 😂 😮. [Code]
RG-L2   Sur une même publication, un utilisateur laisse au plus un like par type d'emoji,
        donc au maximum 4 likes (un 👍, un ❤️, un 😂, un 😮). Le trio utilisateur + publication +
        emoji est unique. [Code (TModeler ne gère pas l'unicité sur plusieurs champs)]
RG-L3   Cliquer à nouveau sur un emoji déjà donné retire ce like. [Code]
RG-L4   Chaque ajout de like ajoute 1 à likesCount, chaque retrait enlève 1 ; le compteur
        ne descend jamais sous 0. [Code]
RG-L5   Liker sa propre publication : à décider par l'équipe. [Décision d'équipe]


Commentaires et réponses
------------------------
RG-K1   Un commentaire ou une réponse n'est pas vide. [Code]
RG-K2   Une réponse se rattache à un commentaire, jamais à une autre réponse : un seul
        niveau de réponses. [TModeler (Reply pointe vers Comment)]
RG-K3   Chaque nouveau commentaire ajoute 1 à commentsCount de la publication. [Code]
RG-K4   Les commentaires et les réponses ne peuvent être ni modifiés ni supprimés pour
        l'instant (hors périmètre). [Code]
RG-K5   Les commentaires s'affichent du plus récent au plus ancien ; les réponses d'un
        commentaire, dans l'ordre chronologique. [Code]


Médias
------
RG-F1   Tous les fichiers passent par un seul modèle Media, qui contient la référence du
        fichier, jamais son contenu. [TModeler]
RG-F2   Le type d'un média vaut obligatoirement image, audio ou video. Le type legende ne
        concerne que les publications sans média. [Code]
RG-F3   Une vidéo fait 100 Mo maximum (contrôle sur sizeBytes avant l'enregistrement).
        [Code]
RG-F4   Les fichiers sont stockés dans le navigateur, dont l'espace est limité : en cas de
        quota dépassé, l'enregistrement est refusé avec un message clair. [Code]
RG-F5   Dans les listes (conversations, messages), on ne charge pas le fichier lui-même :
        on le charge seulement au moment de l'afficher. [Code]


Règles techniques TModeler
--------------------------
RG-T1   Chaque TextField et chaque BoolField a un .default(...), sinon la lecture plante
        sur le web. [TModeler]
RG-T2   Les dates et les grands nombres ne vont jamais dans un FloatField : utiliser
        TimeField ou IntField. [TModeler]
RG-T3   Toujours vérifier available() avant de lire une relation. [Code]
RG-T4   Les filtres et les tris sont faits dans la requête TModeler, jamais en Kotlin
        après avoir tout chargé. Une liste se charge avec un TFlow, jamais avec all(). [Code]
RG-T5   La base locale est nommée nom-DB_VERSION. Après toute modification de la structure
        d'un modèle, incrémenter DB_VERSION dans NGomaCore.kt. [Code]



6. MODÈLES TMODELER (KOTLIN)
============================

Emplacement : core/src/commonMain/kotlin/ai/tambo/foundation/ngoma/models/, une classe par
fichier (User.kt, Message.kt…). Chaque fichier commence par le package et les imports
ci-dessous (ne garder que ceux utilisés).

    package ai.tambo.foundation.ngoma.models
    
    import ai.tambo.tmodeler.field.common.TextField
    import ai.tambo.tmodeler.field.common.IntField
    import ai.tambo.tmodeler.field.advanced.BoolField
    import ai.tambo.tmodeler.field.advanced.TimeField
    import ai.tambo.tmodeler.field.advanced.ModelField
    import ai.tambo.tmodeler.field.media.FileField
    import ai.tambo.tmodeler.model.TModel
    import ai.tambo.tmodeler.model.TMignore
    import ai.tambo.tmodeler.ms.Tms


> Gestion des utilisateurs
    class User : TModel<User>() {
        var name         = TextField().default("")
        var phone        = TextField().default("").unique()
        var passwordHash = TextField().default("")
        var active       = BoolField().default(true)
        var createdAt    = TimeField()
    
        @TMignore var name_         by name
        @TMignore var phone_        by phone
        @TMignore var passwordHash_ by passwordHash
        @TMignore var active_       by active
        @TMignore var createdAt_    by createdAt
    
        companion object { val tms by lazy { Tms(User::class) } }
    }
    
    class Session : TModel<Session>() {
        var currentUser = ModelField(User::class)
    
        @TMignore var currentUser_ by currentUser
    
        companion object { val tms by lazy { Tms(Session::class) } }
    }

        var createdAt     = TimeField()

        companion object { val tms by lazy { Tms(Conversation::class) } }
    }

        var conversation = ModelField(Conversation::class)
